# AI更新リマインダー設計｜契約・ドメイン・サブスクの期限切れを防ぐ

「ドメインの更新を忘れてWebサイトが停止した」「無料期間が終わり、使っていないサービスに課金された」「契約の解約期限を過ぎて自動更新された」——こうしたトラブルは、個人事業主や中小企業で起こりがちです。

契約やサブスクが増えるほど、カレンダーへの手入力だけでは管理が難しくなります。担当者の異動やメールの見落としも、期限切れを招く原因です。

そこで役立つのが、AIと自動化ツールを組み合わせた更新リマインダーです。本記事では、契約・ドメイン・サブスクを一元管理し、期限前に必要な判断と行動を促す仕組みの作り方を解説します。

## 更新管理でよくある3つの失敗

### 1. 更新通知メールだけに頼る

サービス事業者から届くメールは、迷惑メールへの振り分けや担当者変更によって見落とされる可能性があります。また、更新直前に通知されても、社内承認や比較検討が間に合わないことがあります。

### 2. 期限だけを記録する

更新日だけでは、適切な判断ができません。少なくとも次の情報が必要です。

- 解約申請の期限
- 自動更新の有無
- 更新料金
- 支払方法
- 契約責任者
- 実際の利用状況
- 更新時に必要な承認

契約終了日が12月31日でも、解約通知が「終了日の60日前まで」と定められていれば、実質的な判断期限は11月1日です。

### 3. 一度通知して終わる

通知を受け取っても、忙しいと後回しになります。更新管理には、早期確認・判断・最終確認という複数段階の通知が必要です。

## AI更新リマインダーの基本設計

AIを導入する目的は、単に通知文を作ることではありません。契約情報を整理し、優先順位を付け、担当者が判断しやすい形で知らせることが重要です。

基本構成は次のとおりです。

1. 契約情報を台帳に集約する
2. 更新日と解約期限を登録する
3. 複数回の通知ルールを設定する
4. AIで要約と対応案を生成する
5. 更新・解約の結果を記録する

AIに契約書を読み取らせる場合でも、最終判断は原本を確認してください。特に解約条件、違約金、自動更新条項は、人による確認が必要です。

## 管理対象ごとの比較表

| 管理対象 | 主なリスク | 記録すべき項目 | 推奨通知時期 |
|---|---|---|---|
| ドメイン | サイト・メールの停止 | ドメイン名、管理会社、更新日、自動更新、決済方法 | 90日前、30日前、7日前 |
| SaaS・サブスク | 不要な継続課金 | プラン、料金、請求周期、利用人数、解約期限 | 60日前、30日前、7日前 |
| 業務委託契約 | 意図しない自動更新 | 契約期間、通知期限、担当者、更新条件 | 90日前、60日前、30日前 |
| SSL証明書 | 警告表示・通信障害 | 対象サイト、有効期限、自動更新、管理者 | 60日前、30日前、14日前 |
| サーバー・クラウド | サービス停止・過剰コスト | 契約期間、料金、利用量、移行期間 | 90日前、60日前、30日前 |
| 保守・ライセンス | サポート停止 | 製品名、数量、更新料金、利用部門 | 90日前、45日前、14日前 |

すべてを同じタイミングで通知する必要はありません。移行に時間がかかるサービスや、事業への影響が大きい契約ほど早く通知します。

## AI更新リマインダーを作る具体的な手順

### 手順1：契約・サブスクを棚卸しする

まず、現在支払っている契約を洗い出します。

確認先は、クレジットカード明細、銀行口座、会計ソフト、メール、アプリストア、各部署の経費申請などです。年払いのサービスは月次明細だけでは見つけにくいため、過去12〜13か月分を確認しましょう。

見つけた契約は、次の形式で台帳に登録します。

| 項目 | 記入例 |
|---|---|
| サービス名 | レンタルサーバーA |
| カテゴリ | サーバー |
| 契約責任者 | Web担当者 |
| 更新日 | 20XX年10月31日 |
| 解約期限 | 更新日の30日前 |
| 料金 | 年額○○円 |
| 自動更新 | あり |
| 支払方法 | 法人カード |
| 重要度 | 高 |
| 管理画面URL | ログインページ |
| 備考 | 解約前にデータ移行が必要 |

パスワードやカード番号を台帳へ直接記載するのは避け、パスワード管理ツールへの参照情報だけを保存します。

### 手順2：管理ツールを選ぶ

更新管理には、表計算、データベース型ツール、専用の契約管理サービスなどを利用できます。

| 方法 | 向いている人 | メリット | 注意点 |
|---|---|---|---|
| Googleスプレッドシート | 個人・小規模チーム | 低コストで始めやすい | 通知設定に追加作業が必要 |
| Notion | 情報をまとめたいチーム | 契約資料や議事録と連携しやすい | 複雑な自動化には外部連携が必要 |
| Airtable | 多数の契約を管理するチーム | データ整理と自動化に強い | 件数に応じて費用が増える |
| 契約管理システム | 契約書が多い企業 | 検索、権限、監査に対応しやすい | 導入・運用コストがかかる |
| タスク管理ツール | 更新作業を担当者へ割り当てたい組織 | 対応状況を可視化できる | 契約原本の保管には不向き |

小規模なら、スプレッドシートとカレンダーの組み合わせから始めても十分です。

### 手順3：重要度を分類する

契約ごとに重要度を「高・中・低」で分類します。

- 高：停止すると売上、顧客対応、セキュリティに影響する
- 中：代替可能だが、移行準備が必要
- 低：停止しても業務への影響が小さい

ドメイン、メール、サーバー、決済サービスは原則として重要度「高」です。高重要度の契約では、通知先を担当者だけでなく管理者にも設定します。

### 手順4：段階的な通知を設定する

実用的な通知スケジュールの例は次のとおりです。

- 90日前：代替サービスの調査、予算確認
- 60日前：利用状況と更新条件の確認
- 30日前：更新・解約の社内決定
- 14日前：申請や支払い状況の確認
- 7日前：未対応案件の緊急通知
- 翌日：更新・解約結果の記録依頼

「更新日の30日前」ではなく、「解約期限の30日前」を起点にすることがポイントです。

### 手順5：AIで通知内容を判断しやすくする

AIには、台帳の情報を基に次の内容を生成させます。

- 契約内容の短い要約
- 更新料金と前回料金の比較
- 利用人数や利用頻度
- 継続・縮小・解約の選択肢
- 期限までに必要な作業
- 担当者への確認事項

プロンプト例は以下のとおりです。

> 以下の契約情報を、更新責任者向けに200字以内で要約してください。更新日、解約期限、料金、利用状況、未確認事項を明記し、「更新」「プラン変更」「解約」の判断材料を箇条書きにしてください。情報が不足している場合は推測せず、要確認と表示してください。

機密性の高い契約書を扱う場合は、利用するAIサービスのデータ保持方針、学習利用の有無、組織向け管理機能を確認してください。

## 収益改善につながる更新判断の基準

期限切れを防ぐだけでなく、不要な支出を減らすことも更新管理の目的です。更新前には次の数字を確認しましょう。

- 直近90日間の利用回数
- 契約アカウント数と実利用者数
- 1人当たり、または1回当たりのコスト
- 同じ機能を持つ別サービスの有無
- 無料・低価格プランへ変更できるか
- 解約した場合の移行コスト
- 年払いによる割引と資金負担

たとえば、10アカウントを契約していて実利用者が4人なら、解約ではなく席数削減が有効です。AIには利用データの集計を補助させ、最終的な更新判断は費用と業務影響の両面から行います。

## 運用を形骸化させないポイント

台帳を作っても、更新されなければ役に立ちません。毎月1回、次の項目を確認する運用を設けます。

- 新しい契約が登録されているか
- 担当者や支払方法に変更がないか
- 90日以内に期限を迎える契約はあるか
- 通知後も未対応の案件はないか
- 解約済みサービスへの請求が続いていないか

また、新規契約時に台帳登録を必須化すると、後から探す負担を減らせます。「契約した人が登録する」だけでなく、経理や管理者が月次で照合する二重チェックが効果的です。

## FAQ

### Q1. カレンダーへの登録だけでは不十分ですか？

契約数が少なければ可能ですが、料金、解約期限、担当者、対応状況まで管理するには不十分です。カレンダーは通知用、契約台帳は情報管理用として併用するのがおすすめです。

### Q2. 通知は何日前に設定すべきですか？

一般的には90日、60日、30日、7日前が目安です。ただし、契約上の解約期限や移行に必要な期間を優先してください。ドメインや基幹サービスは、より早い段階から確認します。

### Q3. AIに契約書を読み込ませても安全ですか？

サービスの利用規約やデータ管理方法によります。機密情報を扱う場合は、法人向けプラン、アクセス制御、ログ管理、データ保持設定を確認してください。許可なく個人情報や秘密情報を入力しない運用も必要です。

### Q4. 自動更新はすべて解除したほうがよいですか？

一律解除はおすすめできません。ドメインやサーバーなど、停止時の影響が大きいものは自動更新を有効にし、決済エラーを監視するほうが安全です。不要になりやすいサブスクは、更新前の確認を厳格にします。

### Q5. 個人事業主でも専用システムは必要ですか？

契約数が少なければ、スプレッドシートとカレンダーで始められます。契約数が増えた段階で、データベース型ツールや自動化サービスへ移行すると無駄がありません。

## まとめ｜まずは更新期限の一覧化から始めよう

AI更新リマインダーは、期限を知らせるだけの仕組みではありません。契約情報を一元化し、更新・縮小・解約を期限前に判断できる状態を作るものです。

まずは過去12〜13か月分の支払いを確認し、契約名、更新日、解約期限、料金、自動更新、担当者を一覧にしてください。その後、重要度の高い契約から段階的な通知を設定します。
